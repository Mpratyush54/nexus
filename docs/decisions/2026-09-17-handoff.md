# Session & Task Handoff Protocol — Phase Decisions

Date: 2026-09-17
Scope: `internal/handoff/handoff.go` for nexus issue #23 (Session & Task
Handoff Protocol) — human-to-human (Alice → Bob) and agent-to-agent
(Claude → Copilot/Cursor) transfers.
Status: implemented stdlib-only, covered by round-trip / lock / translation
tests; event persistence stays with the caller's `store.AppendEvent`.

## Decision 1 — why a self-contained package shape

`HandoffPackage` snapshots exactly four things — active `TaskStatus`,
ephemeral `MemorySnippet`s, `ModifiedFiles`, and `BranchState` — plus
from/to routing and accept stamps. Alternatives considered:

- **Reusing `store.Task` / `store.MemoryItem` directly.** Rejected: it would
  couple a coordination protocol to the Postgres schema and force a DB import
  into every consumer (daemon, MCP server, WS hub). Snapshots are also the
  correct semantics — the receiver needs the task *as it stood at handoff*,
  not a live foreign key that keeps mutating underneath.
- **One mega-struct with full session dump.** Rejected: sessions can be
  multi-hour with large transcripts; the handoff carries only what the next
  worker needs to resume (task + working memories + file pointers + branch),
  keeping the `SESSION_HANDOFF_INITIATED` payload small and the privacy
  surface minimal (no full transcript leaves the session).
- **Builder returns `(pkg, Event)` pair.** The package is the transferable
  artifact; the event is the audit trail. Callers persist the event via the
  existing append-only log (`store.AppendEvent`) and ship the package
  out-of-band (WS fan-out, MCP response, instruction-file write), so neither
  layer can drift from the other — both derive from the same constructor.
- **`AcceptHandoff` mutates in place and re-points `Task.AssignedTo`.**
  Assignment transfer is the observable proof of handoff; stamping
  `Accepted/AcceptedBy/AcceptedAt` on the same struct keeps build→accept a
  closed round-trip the tests can assert without a database.

## Decision 2 — why advisory locks, not mandatory locks

`LockSet` is a `map[file]owner` under a mutex: `Acquire` fails with
`ErrLocked` on conflicting owners, `LockAll` rolls back partial takes, and
`Release`/`UnlockAll` are owner-scoped. This is deliberately **advisory**
(cooperative), not mandatory (OS-enforced `flock`):

- Handoffs span machines and processes (Alice's laptop → Bob's laptop,
  Claude → Cursor on another host). An OS lock cannot cross that boundary;
  a lock map carried alongside the handoff (sender locks modified files,
  receiver waits or explicitly overrides) can.
- Mandatory locks risk wedging the tree when a holder crashes mid-handoff.
  Advisory locks degrade gracefully: holders are visible (`Holder`), cleanup
  on accept/cancel is idempotent (`UnlockAll` skips non-owned files), and a
  human can always see *who* holds a file and steal it with intent — the
  failure mode is a visible conflict error, never a stuck filesystem.
- Enforcement lives where writes actually happen (daemon file-watcher /
  interceptor path consults the set before writing), so the protocol stays
  transport-agnostic and testable in-memory with zero syscalls — matching the
  repo's stdlib-only hub precedent (decisions/2026-09-17-sessions-ws.md).

## Decision 3 — why per-agent translation

`TranslateForAgent` renders the same package into the incoming agent's
preferred interface instead of forcing one canonical format:

- **Claude-family → `mcp-context-block`.** Claude Code / MCP consumers ingest
  structured XML context (`<handoff_context>` with task, session memories,
  modified files, branch). Emitting that shape directly means zero re-prompt
  and zero re-parsing: the block drops into the existing context builder /
  MCP response path verbatim.
- **Copilot / Cursor → `instruction-file`.** File-driven agents read
  checked-in instructions (`.github/muse-instructions.md`,
  `.cursorrules`). A markdown handoff section with the active task, session
  context bullets, files-in-progress, and branch state gives the receiver
  durable, versioned context that survives restarts — the file path is named
  in the output so automation knows exactly where to write.
- **Anything else → generic markdown.** New agents (OpenCode, custom bots)
  get a readable fallback rather than an error, so the protocol stays open
  without a registry update per tool.

One renderer per family (not per version) keeps the matrix small: agent
detection is substring-based (`claude` / `copilot` / `cursor`), so
`claude-code`, `github-copilot`, etc. all resolve without exact-match
brittleness. Content is always fully rendered even for empty packages
(skeletal but valid), so callers can inject it unconditionally.

## Non-goals

Binary attachments, full-transcript shipping, and cross-project handoffs are
out of scope — the package carries pointers (file paths, branch+commit),
not contents. Presence/heartbeat during the handoff window reuses the
existing 90 s session-presence contract rather than inventing a new one.
