# Cross-Platform Daemon Service Management (`internal/platform`) — 2026-09-17

Issue: Mpratyush54/nexus#24 (`[Daemon] Cross-Platform Daemon Service
Management & Auto-Start (platform/)`).
Scope: `internal/platform/` only — `platform.go`, `windows.go`, `darwin.go`,
`linux.go`, `platform_test.go`. `cmd/nexus` untouched; the CLI hooks are
exposed as `platform.Install` / `platform.Uninstall` / `platform.Status`
(`nexus daemon install|uninstall|status` wiring is a follow-up in the CLI).

## Decision 1 — one `Service` interface, OS backends behind build tags

Why:

- The plan's target tree already reserves `platform.go` as
  `Interface: ServiceInstall, ConfigDir, ProjectRoots` with per-OS files.
  A `Service` interface (`Install(executable, args)`, `Uninstall()`,
  `Status()`) plus a `Current()` factory keyed on `runtime.GOOS` keeps every
  caller (daemon, CLI) portable: they branch never.
- Build tags (`//go:build windows|darwin|linux`, matching the existing
  `internal/daemon/fileops_windows.go` / `fileops_unix.go` convention) mean
  each binary compiles only its own backend — no `schtasks` strings on macOS,
  no `launchctl` on Windows — while the pure renderers stay in the shared
  `platform.go` so tests run green on any GOOS.
- `Status()` returns a closed enum
  (`not-installed|running|stopped|unknown`) instead of bools, so the CLI can
  distinguish "never installed" (actionable: run install) from "installed
  but down" (actionable: start) from "scheduler unreachable".

## Decision 2 — native scheduler per OS: schtasks / launchd / systemd

Why:

- Windows: `schtasks /Create /SC ONLOGON` ships with every Windows SKU, needs
  no admin install path and no third-party service wrapper (which would add a
  `go.mod` dependency and a Windows-only binary). An ONLOGON task is the
  least-privilege way to meet "starts on user login".
- macOS: `launchd` (`~/Library/LaunchAgents/*.plist` + `launchctl
  bootstrap`) is the only Apple-blessed login-start mechanism; cron is
  deprecated and Login Items require GUI plist juggling. `RunAtLoad` +
  `KeepAlive` gives restart-on-crash for free.
- Linux: a `systemd --user` unit (`~/.config/systemd/user/*.service`,
  `WantedBy=default.target`, `enable --now`) is the login-session standard
  on all mainstream distros and needs no root. `Restart=on-failure` mirrors
  the launchd KeepAlive behavior.
- All three backends are thin `os/exec` wrappers over generators that are
  pure functions — the OS tool does the scheduling, our code only renders
  text, so there is nothing to port when the next OS version changes flags.

## Decision 3 — paths via `os.UserConfigDir` / `os.UserCacheDir`, never literals

Why:

- The issue's acceptance criterion is zero hardcoded `D:\` paths. Every path
  derives from stdlib (`os.UserConfigDir` → `%APPDATA%\nexus`,
  `~/Library/Application Support/nexus`, `~/.config/nexus` per OS;
  `os.UserCacheDir` for caches; `os.UserHomeDir` for the default project
  root), with `NEXUS_CONFIG_DIR` / `NEXUS_CACHE_DIR` / `NEXUS_PROJECT_ROOTS`
  env overrides for tests, CI, and multi-checkout machines.
- Per-OS mapping is isolated in pure `configDirForGOOS` / `cacheDirForGOOS`
  helpers taking plain strings, so tests assert Windows/darwin/linux layouts
  on any host without switching `GOOS` or touching the registry.
- `ProjectRoots()` returns configuration, not code: env list wins, home dir
  is the default, and no drive letter appears anywhere in the package
  (enforced by `TestNoHardcodedDrivePaths`, which scans the package sources
  for drive literals).

## Decision 4 — stdlib only, no new dependencies

Why:

- `go.mod` carries only pgx/pgvector lines; prior decision docs (CLI,
  interceptor-watcher, harvester) consistently defer deps to the
  Postgres/daemon phases. Service management needs none: `os/exec` drives
  schtasks/launchctl/systemctl, `os` + `path/filepath` build paths,
  `strings` renders units/plists.
- XML for the plist is hand-escaped (`plistEscape`, five entities) rather
  than `encoding/xml` struct tags so `ProgramArguments` stays an exact
  argv array with no shell-quoting layer on macOS, while systemd/schtasks
  share one tested `quoteArg`/`execCommandLine` quoting path.
