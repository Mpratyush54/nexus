# Episodic Engine — Decisions (issue #11, Phase 2.3/2.4/2.5)

Date: 2026-09-17. Scope: `internal/store/episode_extra.go`,
`internal/store/episode_extra_test.go` only — `episodes.go` (foundation),
`store.go`, and all other files untouched. Every choice below carries
Context / Decision / Alternatives / Why / Consequences.

---

## 1. New file `episode_extra.go`, never edit `episodes.go`

- **Context:** `episodes.go` is foundation-owned (issue #2/#9 era Postgres
  CRUD + ILIKE search). Issue #11 adds auto-detection, linking, exact/file/
  semantic retrieval, and XML rendering on top.
- **Decision:** All Phase 2 work lives in `episode_extra.go` (+ its test);
  `episodes.go` is read but not modified. Extra capabilities are new methods
  on `MemStore`/`PostgresStore` (same package) plus pure helpers
  (`AutoDetectEpisode`, `CosineSimilarity`, `ToXML`) — no `Store` interface
  change, no migration.
- **Alternatives:** (a) Extend `episodes.go` in place — collides with the
  foundation owner and mixes CRUD with heuristics. (b) New package
  `internal/episodes` — would need exported store internals or duplicate
  scan helpers; same-package methods reuse `scanEpisode`, `episodeColumns`,
  `encodeEmbedding`, `ErrNotFound` for free.
- **Why:** Zero merge conflicts with foundation work; `git log` cleanly
  attributes the engine to #11; deletion/rollback is one file.
- **Consequences:** Two files define methods on the same types — contributors
  must check both. Mitigated by the header comment in `episode_extra.go`
  listing exactly what lives where.

## 2. Cosine similarity reused for semantic search (MemStore mirrors `<=>`)

- **Context:** Plan §2.4 ranks episodes by pgvector cosine distance
  (`embedding <=> $2`); tests must run with no database via `MemStore`.
- **Decision:** Exported `CosineSimilarity(a, b []float32) float64`, used by
  `MemStore.SearchEpisodesSemantic` (rank desc, limit default 5 per plan).
  pgvector's `<=>` orders by `1 − cosine_similarity`, so descending cosine
  reproduces production ordering exactly. Zero/empty/dim-mismatch inputs
  return 0, never NaN (unembedded episodes sort out, never crash ranking).
- **Alternatives:** (a) Euclidean distance — would NOT match `<=>`
  ordering, tests would certify a different ranking than prod serves.
  (b) Test-only helper — hides the math the Context Builder (Phase 2.5)
  depends on for auto-injection.
- **Why:** One math, two backends: MemStore tests predict Postgres behavior.
  `PostgresStore.SearchEpisodesSemantic` uses the same `<=>` operator as
  `SearchMemoryVector` (plan §1.5), so both memory and episode semantic
  paths share one operator and one index family (IVFFlat cosine).
- **Consequences:** Embeddings must be same-dimension on both sides;
  mismatches silently score 0 (documented). Newton's-method sqrt avoids a
  new import for one call site — replace with `math.Sqrt` if it ever shows
  in profiles (it won't; ranking is O(n·d)).

## 3. Role enum as Go constants validated at the boundary

- **Context:** `episode_events.role` has a SQL CHECK constraint
  (`trigger|investigation|attempt|fix|verification|context`, plan §1.1).
- **Decision:** `EpisodeRole*` constants + `ValidEpisodeRole()`, enforced in
  both `LinkEpisodeEvent` implementations before any write. Six roles, not
  five: `attempt` (a fix that failed) is distinct from `fix`, and `context`
  covers background reads that informed the arc without being causal.
- **Alternatives:** (a) Free-form strings — Postgres rejects them with raw
  constraint errors; MemStore would accept garbage, backends diverge.
  (b) Typed `Role string` — Go-idiomatic but adds conversion friction at
  every JSON/SQL boundary for no runtime gain.
- **Why:** Invalid roles fail fast with a readable error naming the enum;
  Go and SQL can never disagree because the constant block mirrors the
  migration CHECK list 1:1.
- **Consequences:** Adding a role requires migration + constant + validator
  in lockstep — intentional, keeps the three copies honest.

## 4. Links ride on `Event.EpisodeID` + payload role keys (MemStore)

- **Context:** `MemStore` has no `episodeEvents` map and `store.go` is
  off-limits, yet `LinkEpisodeEvent`/`GetEpisodeTimeline` need link state.
- **Decision:** Stamp `Event.EpisodeID` and `episode_role`/`episode_note`
  payload keys on the existing `s.events` slice; timeline = filter by
  `EpisodeID`, sort by ID ascending. Postgres writes the real
  `episode_events` row AND backfills `events.episode_id`; its timeline reads
  both bases (`IN (SELECT …)` OR `episode_id =`) so either write path is
  visible.
- **Alternatives:** (a) Package-global link map — hidden state, leaks across
  tests, race-prone. (b) Edit `store.go` to add the map — violates the
  do-not-touch constraint and changes the shared struct.
- **Why:** Zero structural changes, no new synchronization (existing mutex
  covers it), and the link travels with the event through `Subscribe`/
  `ListEvents` fan-out for free.
- **Consequences:** Payload gains two reserved keys (`episode_role`,
  `episode_note`) — documented as constants; producers must not reuse them.
  Re-linking an event moves it (one `EpisodeID` per event); multi-episode
  membership uses Postgres `episode_events` only.

## 5. Exact `= ANY` retrieval alongside ILIKE search (not instead)

- **Context:** `SearchEpisodes` does ILIKE substring matching (good recall,
  noisy). Plan §2.4 specifies exact `$2 = ANY(error_patterns)` for the
  Context Builder's auto-injection (Phase 2.5): a failing command's stderr
  line must hit the one prior fix, not every episode mentioning "timeout".
- **Decision:** `SearchEpisodesByErrorPattern` / `SearchEpisodesByFile` use
  exact equality (`MemStore`) and `= ANY` (`Postgres`), ordered by
  `resolved_at DESC` (most recent fix first). Substring/narrative search
  stays in `SearchEpisodes` untouched.
- **Alternatives:** Single fuzzy search for everything — auto-injection
  would surface stale/wrong fixes into agent context, the exact failure
  mode episodes exist to prevent.
- **Why:** Precision where automation consumes it (auto-inject), recall
  where humans browse (dashboard/`episode_search`). Tests pin the boundary:
  `"connection"` does NOT exact-match `"connection refused"`.
- **Consequences:** Callers must pick the right method; MCP `episode_search`
  should fan out exact → file → semantic and merge (server-side work,
  out of scope for #11).

## 6. `AutoDetectEpisode` is a pure function returning a draft

- **Context:** Plan §2.3's heuristic (fail → reads → modify → pass →
  commit) runs in the Memory Processor, which is unimplemented; the store
  must not invent persistence or LLM calls.
- **Decision:** `AutoDetectEpisode(events, projectID) (*Episode, bool)` —
  sorts a copy by ID, finds the first failing `COMMAND_EXECUTED`, walks the
  post-trigger window, returns an `OPEN`/`bug_fix` draft or `(nil, false)`.
  `RootCause` is explicitly labeled a heuristic guess; `Resolution` fills
  only from an observed `GIT_COMMITTED`, `Verification` only from a
  same-command exit-0 run. Payload readers tolerate int/float64/string exit
  codes and `command|cmd`, `stderr|error|output`, `path|file` key variants.
- **Alternatives:** (a) Store method that inserts the episode — untestable
  without policy for duplicates/ownership, and the Processor (not the
  store) owns lifecycle. (b) LLM-based classification now — no LLM
  dependency exists in `internal/store`; heuristic first, LLM refinement
  later.
- **Why:** Pure = trivially tested (failure arc, clean window, empty
  window), reusable by daemon/processor/server alike, and honest about what
  it knows (guess labeled as guess).
- **Consequences:** First-failing-command wins per window; overlapping arcs
  need window-splitting upstream (Processor concern). `error_patterns`
  takes the first stderr line only — multi-line signatures are a
  verification-time refinement.

## 7. `ToXML` emits a stable full-arc shape, always escaped

- **Context:** Plan §2.4 fixes the inference XML (`trigger`,
  `investigation`, `root_cause`, `resolution`, `verification`, `events
  count`); the Context Builder (Phase 2.5) will embed it in agent context.
- **Decision:** `(*Episode).ToXML()` / `ToXMLWithEvents(events)` always emit
  all five arc tags (empty when unset — stable shape for parsers),
  `encoding/xml.EscapeText` on every text/attribute, `files="a, b"` on
  `resolution` only when non-empty, RFC3339 `date` on `trigger` only when
  set.
- **Alternatives:** Omit empty tags — smaller output but shape-shifting XML
  forces defensive parsing in every consumer.
- **Why:** LLMs and XML parsers both do better with a fixed schema;
  escaping is non-negotiable (triggers contain raw stderr with `<>&`).
- **Consequences:** Slightly verbose for sparse drafts — acceptable inside
  the token-budgeted `<recent_episodes>` section, which truncates by
  section, not by tag.
